## 確認済み

- Vitest：ルール・RoomSession（同時更新の再試行・退出）・Supabase クライアント（呼び出しの形・エラー変換）
- PostgreSQL 16：マイグレーションと権限・RPC のテスト（テーブルを直接読めない、token なし・部外者は読めない／保存できない、同時更新の検出、退出、閉じた部屋）
- Playwright：お試しモードで2タブを使い、作成 → 招待リンクで参加 → 設定 → 準備 → 対戦（複数ターン）→ 終了 → 再読み込みで復帰 → もう一度 → 退出の通知 → 存在しないコード。ライト・ダーク両方
- Playwright：Supabase の RPC と Realtime（WebSocket・REST の Broadcast）を模倣して、別端末2台で作成 → 参加 → 対戦（終了まで）→ 再読み込みで復帰 → ホスト退出の通知まで。相手の画面は Broadcast で 0.1 秒以内に変わった

### M5〜M7 で確認したこと

- Vitest：手札の持ち越し・出会った問題を配らない・古い順の再出題・ジャンルの散らし方、成績の集計、ログイン・フィードバックの通信
- PostgreSQL 16：1つ目のマイグレーションの上に2つ目を適用できること。ログイン（大文字小文字・別端末・ログアウト）、部屋、記録（再送しても二重にならない・壊れた state でも止まらない）、持ち越しの手札（新しい相手が出会った問題は外す）、成績、フィードバックの送りすぎ防止、テーブルを直接読めないこと
- Playwright（お試しモード）：登録 → 2戦（2戦目に新しく配られた問題は1戦目と重ならない）→ 通算成績 → フィードバック → 成績画面 → 再読み込みでログインしたまま → ログアウト → 再ログインでニックネームが入っている
- Playwright（Supabase モード）：一時的な PostgreSQL にマイグレーションを適用し、RPC をそのまま中継して、別端末2台で登録 → 2戦 → フィードバック（`/api/feedback` 経由で保存）→ 成績 → 3台目の端末で同じメールアドレスにログインして同じ成績
